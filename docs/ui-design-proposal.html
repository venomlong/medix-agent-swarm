MEDIX AGENT SWARM · 界面设计方案

可视化交互界面

清新自然 · 让协作过程可见

为 medix-agent-swarm 多智能体医疗助手设计的 Web 交互界面提案。 项目目前仅有命令行入口，多 Agent 协作、Skill 调用、安全修复等最有价值的过程全部藏在日志里； 复杂问题需等待 30–90 秒且无中间反馈。本方案将这些过程变成用户可见、可回看的界面， 并以自然物候的设计语言传递医疗产品应有的安心感。

01

目标用户

同一套工作台服务三类场景：作者调试、评审演示、真实咨询。过程可视化是共同需求。

开发者（项目作者）

调试与观察多 Agent 协作：路由决策、子任务状态、Skill 调用、事件流、约束违规与修复记录。

演示 / 评审观众

面试或汇报场景，直观看到「群体智能」的实际工作过程——这是纯 CLI 无法呈现的核心卖点。

健康咨询使用者

以对话方式提问，获得流式答案、核心建议、依据来源与安全提示；长等待被过程动画化解。

02

技术选型

本场景是服务端向浏览器的单向推送。SSE 更简单、可走普通 HTTP、断线自动重连；WebSocket 留到需要「中途干预 Agent」时再升级。

推荐 · 正式方案

FastAPI + SSE + React（Vite + TypeScript）

后端在现有代码之上加一层薄服务：POST /chat 返回 SSE 流， EventBus 订阅 SharedContext 事件实时推送；SwarmCoordinator 改为应用级单例 （消除每次请求重建 Agent 池的开销）。前端 React 自由实现「清新自然」主题与 Agent 时间线动画。 开发成本约 2–3 周。

备选 · 内部快速原型

Gradio / Streamlit

开发成本低（1–2 天），但整体刷新、难做时间线动画，视觉受模板限制，「清新自然」难以落地。

备选 · 将来升级

FastAPI + WebSocket + React

双向通信，视觉能力与推荐方案相同。需处理连接状态；待将来需要「中途干预 Agent」时再升级。

方案实时事件流视觉定制开发成本结论
FastAPI + SSE + React 原生支持，逐事件推送 完全自由，可精确落地设计语言 中（约 2–3 周） 推荐 · 正式方案
Gradio / Streamlit 弱（整体刷新） 受模板限制 低（1–2 天） 备选 · 快速原型
FastAPI + WebSocket + React 双向通信 同推荐方案 中高 待需要中途干预时升级

04

「清新自然」设计语言

医疗助手需要传递「安心、温和、专业」。方案以自然物候为意象：鼠尾草绿为主色，米白纸感做底， 木色与陶土做点缀；标题用衬线字体带出人文感，大圆角与充足留白降低界面的紧张度。

鼠尾草绿主色 米白纸感底色 木质点缀 衬线标题 大圆角 呼吸式留白

依赖与顺序建议

· M1 前建议先修 IMPROVEMENT_PLAN 中的 Bug 7（同步调用阻塞事件循环），否则 SSE 推送会被 embedding / Mem0 调用卡顿。

主要风险与缓解

· 复杂问题耗时 30–90s：以过程时间线 + 流式答案化解等待焦虑（本方案核心价值）。

· LLM 路由波动导致演示不稳定：配合 P0-1 路由确定性改造，UI 上明示路由理由。

· Windows 开发环境：全栈本地可跑（Milvus Lite 文件库 + Vite dev server），无容器依赖。
